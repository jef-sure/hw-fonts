# Формат файла шрифта

Редактор сохраняет шрифт в один JSON-файл (кнопка «Download font»). Здесь
описано, что значит каждая его часть, как по этим данным расставлять символы
в строке и как соединять буквы при слитном письме. Примеры взяты из
`font0-ss.json`.

## Сетка и координаты

- Все точки — целые числа на сетке 256×256, от 0 до 255. Ось X идёт вправо,
  ось Y — вниз.
- Координаты точек абсолютные, от левого верхнего угла сетки, а не от
  активной области.
- Символ рисуется в активной области — прямоугольнике внутри сетки. Вокруг
  неё остаются поля: туда выходят опорные точки кривых и хвосты букв.
- Все размеры и длины в файле — в клетках этой сетки.

## Общий вид

```json
{
    "format": "hw-font",
    "formatVersion": 1,
    "name": "font0-ss",
    "baseLine": 139,
    "xHeight": 58,
    "symbolSpace": 16,
    "spaceWidth": 40,
    "symbolOffsetX": 66,
    "symbolOffsetY": 48,
    "symbolSizeX": 100,
    "symbolSizeY": 202,
    "widthType": "fixed",
    "auxilarySegments": [ ...элементы... ],
    "codePoints": {
        "1100": { ...символ «ь»... },
        ...
    }
}
```

## Поля шрифта

| Поле | Смысл | В `font0-ss` |
| --- | --- | --- |
| `format` | Тип файла, всегда `hw-font`. По нему конвертер узнаёт, что это шрифт этого редактора | `hw-font` |
| `formatVersion` | Версия формата, целое число. Растёт, когда файл нового формата нельзя прочитать как старый; новые необязательные поля версию не меняют. Сейчас 1 — формат, описанный здесь | 1 |
| `name` | Название шрифта, оно же имя файла при сохранении | `font0-ss` |
| `symbolOffsetX`, `symbolOffsetY` | Левый верхний угол активной области на сетке («Active area offset») | 66, 48 |
| `symbolSizeX`, `symbolSizeY` | Размер активной области («Active area size»). `symbolSizeX` — ширина ячейки символа в шрифте фиксированной ширины; `symbolSizeY` — высота строки | 100, 202 |
| `baseLine` | Базовая линия, на которой стоят буквы. Отсчитывается от `symbolOffsetY`, то есть на сетке это строка `symbolOffsetY + baseLine` | 139, строка 187 |
| `xHeight` | Высота строчных букв над базовой линией («Lowercase height»). Задаёт строчную полосу, см. ниже | 58, строка 129 |
| `symbolSpace` | Промежуток после символа в строке, когда символы ставятся по своей ширине («Space between symbols»). Это значение для всех символов, у которых нет своего `spaceAfter`. Входит в шаг символа; он же — место для соединительной кривой при слитном письме | 16 |
| `spaceWidth` | Шаг пробела, когда символы ставятся по своей ширине («Space width»). Видимый просвет между словами — `symbolSpace` после последней буквы плюс `spaceWidth` | 40, просвет 56 — примерно строчная буква |
| `widthType` | `fixed` — каждый символ занимает всю ячейку `symbolSizeX`; любое другое значение — символы ставятся по своей ширине. В редакторе поля для него нет, меняется только в файле | `fixed` |
| `auxilarySegments` | Вспомогательные линии: общие для всего шрифта направляющие, по которым выдерживаются наклон и высоты букв. Массив элементов того же вида, что в символах. В символы не входят, при выводе текста не нужны | 6 отрезков |
| `codePoints` | Символы. Ключ — код Unicode десятичным числом в виде строки (`"1100"` — это «ь», U+044C) | 153 символа |

При загрузке редактор берёт из файла только эти поля. Незнакомые поля верхнего
уровня он отбрасывает, а если какого-то из перечисленных нет — отказывается
загружать («Bad font format. Absent keys»). Исключения — `xHeight`,
`symbolSpace` и `spaceWidth`: в старых файлах их нет, тогда берутся 58, 16
и `symbolSizeX − symbolSpace`.

Файл без `format` и `formatVersion` редактор считает старым шрифтом и при
сохранении записывает в него текущие значения. Файл с другим `format` или
с `formatVersion` больше известной ему редактор не загружает. Конвертеру
стоит поступать так же, только файл без этих полей не принимать: размеры
и шаг в нём могут быть посчитаны по старым правилам.

### Вспомогательные линии в `font0-ss`

| Линия | Что показывает |
| --- | --- |
| горизонталь на строке 66 | высоту заглавных букв и цифр, 121 над базовой линией |
| горизонталь на строке 129 | высоту строчных букв — ту же, что `xHeight` |
| две наклонные, от строки 187 до 62 | наклон букв |
| вертикали на столбцах 74 и 157 | левую и правую границы буквы |

## Символ

```json
"1100": {
    "mainSegments": [
        {
            "type": "curve",
            "points": [{"x": 85, "y": 129}, {"x": 43, "y": 244}, {"x": 166, "y": 151}, {"x": 80, "y": 158}],
            "length": 133.77
        }
    ],
    "postSegments": [],
    "beginConnection": [ ...одна кривая... ],
    "endConnection": [ ...одна кривая... ],
    "width": 36, "top": -58, "bottom": 0, "left": 10, "right": 45,
    "lineLeft": 10, "lineRight": 45, "lineWidth": 36,
    "upLeft": null, "upRight": null,
    "advance": 52
}
```

### Сегменты

Каждый из четырёх сегментов — массив элементов; пустой массив значит, что
этой части у символа нет.

| Поле | Смысл |
| --- | --- |
| `mainSegments` | Основной рисунок символа |
| `postSegments` | Отложенные штрихи. Тоже часть символа, но пишутся позже: точки над «ё», перекладина «t», черта у «7». Есть у `012457ZfijtzÄÖÜäöüЁЙЭйэё` |
| `beginConnection` | Начальная связь: штрих, которым перо входит в букву при слитном письме |
| `endConnection` | Конечная связь: штрих, которым перо выходит из буквы к следующей |

Рисунок символа — это `mainSegments` и `postSegments` вместе. Связи в рисунок
не входят: это переходы между буквами.

### Свои промежутки

Два необязательных поля символа задаются в редакторе руками («Space of this
symbol») и при сохранении не пересчитываются:

| Поле | Смысл | Если поля нет |
| --- | --- | --- |
| `spaceBefore` | Пустое место перед символом | 0 |
| `spaceAfter` | Промежуток после символа вместо общего `symbolSpace` | `symbolSpace` шрифта |

В `font0-ss` у всех заглавных букв `spaceBefore` 8, `spaceAfter` своего нет
ни у кого.

Какие связи есть, определяет, с чем символ соединяется:

| Символы | `beginConnection` | `endConnection` |
| --- | --- | --- |
| строчные буквы | есть | есть |
| заглавные буквы | нет | есть |
| заглавные `V` и `W` | нет | нет |
| цифры и знаки препинания | нет | нет |

`V` и `W` кончаются завитком наверху: он остаётся в воздухе и выступает
вправо за ширину письма, а следующая буква пишется отдельно.

### Размеры

Размеры редактор считает сам и перезаписывает при каждом сохранении шрифта;
править их руками незачем. Считаются они по рисунку — `mainSegments` и
`postSegments`, без связей — и именно по тем клеткам, которые закрашиваются
при рисовании, а не по опорным точкам кривых.

Отсчёт: по горизонтали — от `symbolOffsetX`, по вертикали — от базовой линии,
отрицательное значение значит «выше неё».

| Поле | Смысл |
| --- | --- |
| `left`, `right` | Самый левый и самый правый столбец всего рисунка |
| `width` | Полная ширина: `right − left + 1` |
| `top`, `bottom` | Самая верхняя и самая нижняя строка всего рисунка. У «у» это −58 и 60: хвост уходит на 60 клеток под базовую линию |
| `lineLeft`, `lineRight` | Левый и правый столбец той части рисунка, что лежит в строчной полосе |
| `lineWidth` | Ширина в строке: `lineRight − lineLeft + 1` |
| `upLeft`, `upRight` | Левый и правый столбец той части рисунка, что лежит выше строчной полосы. `null`, если выше полосы ничего нет |
| `advance` | Шаг: место символа в строке, `spaceBefore + lineWidth + spaceAfter` (без своих промежутков — `lineWidth + symbolSpace`). Следующий символ начинается на этом расстоянии от начала текущего |

Строчная полоса — строки от `baseLine − xHeight` до `baseLine` включительно
(в `font0-ss` строки сетки 129…187). Если в полосе у символа нет ни одной
клетки, `lineLeft`, `lineRight` и `lineWidth` равны полным.

Шаг — то же, что `xAdvance` в растровых шрифтах DGX и advance width
в TrueType, только отсчитывается он от места на `spaceBefore` левее края
символа в строчной полосе (`lineLeft`), а не от полного левого края.

Три набора размеров нужны из-за хвостов рукописных букв:

- **Полные** (`left`, `right`, `width`, `top`, `bottom`) говорят, сколько места
  рисунок занимает на экране.
- **В строке** (`line…`) — сколько места символ занимает в строке. Флажок «б»
  уходит вправо над строкой до столбца 98, но в полосе буква кончается на 51,
  и следующая строчная встаёт сразу за ней, под флажком.
- **Над строкой** (`up…`) нужны, когда рядом два высоких символа. У «Г»
  перекладина идёт вправо до 90, у «Ч» чашка начинается слева с 8 — по одной
  только строчной полосе они наехали бы друг на друга.

Часть рисунка ниже базовой линии места в строке не занимает и нигде отдельно
не хранится.

## Элемент

```json
{
    "type": "curve",
    "points": [{"x": 85, "y": 129}, {"x": 43, "y": 244}, {"x": 166, "y": 151}, {"x": 80, "y": 158}],
    "length": 133.77,
    "pieces": 14,
    "pixels": 124
}
```

| `type` | Точек | Что это |
| --- | --- | --- |
| `curve` | 4 | Кубическая кривая Безье: начало, две опорные точки, конец |
| `curve3p` | 3 | Квадратичная кривая Безье: начало, опорная точка, конец |
| `line` | 2 | Отрезок |
| `dot` | 1 | Точка |

- `points` — точки элемента на сетке. Опорные точки кривых могут лежать
  далеко за пределами самой буквы.
- `length` — геометрическая длина элемента в клетках, с двумя знаками после
  запятой. Это не число закрашенных клеток: элемент делится на 30 отрезков
  между округлёнными до целых точками, и длины отрезков складываются. Поэтому
  она дробная: это сумма корней. Замкнутая кривая, которая возвращается в свою
  начальную точку, имеет обычную ненулевую длину. У отрезка это расстояние
  между концами, у точки 0. Нужна для скорости пера при анимации письма.
- `pieces` — на сколько прямых отрезков надо разделить элемент на родной
  сетке, чтобы ломаная отходила от настоящей кривой не больше чем на
  полклетки. Отрезки равны по параметру кривой. У отрезка это 1, у точки 0,
  у кривых в `font0-ss` — от 1 до 20, в среднем 7,3.

- `pixels` — сколько клеток сетки элемент закрашивает, когда его рисует
  редактор; каждая клетка считается один раз. У точки 1. У кривых это в среднем
  на 11% меньше, чем `length`: шаг по диагонали — одна клетка, но 1,41 длины.
  Горизонтальный или вертикальный отрезок редактор рисует без последней
  клетки, поэтому у него `pixels` равно `length`, а не на единицу больше.

Все три поля редактор пересчитывает при каждом сохранении.

При выводе в другом масштабе число отрезков пересчитывается так:

```
отрезков = ceil(pieces × √масштаб)
```

Корень, а не сам масштаб, потому что отклонение ломаной от кривой падает как
квадрат числа отрезков. Сам редактор пока рисует по старому правилу:
`ceil(length / 6)`, но не меньше 4 и не больше 30.

### Порядок и направление — это путь пера

Порядок элементов в сегменте и направление каждого элемента, от первой точки
к последней, записывают, как буква пишется рукой.

- Если элемент начинается там, где закончился предыдущий, перо не отрывается.
- Если в другом месте — это отрыв пера.

Для готового текста порядок не важен, для анимации письма и морфинга важен.

## Расстановка символов в строке

Шрифт фиксированной ширины (`widthType: fixed`): каждый следующий символ,
включая пробел, ставится через `symbolSizeX`.

Иначе символы ставятся по своей ширине. Положение символа — это сдвиг `s`,
который прибавляется к X всех его точек. Пусть `x` — место в строке, до
которого дошёл текст.

1. Первый символ строки ставится по полной ширине, `s = x − symbolOffsetX − left`,
   чтобы хвост слева не ушёл за край.
2. Остальные встают началом строчной полосы в `x`, отступив на свой
   `spaceBefore`: `s = x − symbolOffsetX − lineLeft + spaceBefore`.
3. Если у предыдущих символов была часть над строкой и у этого она тоже есть
   (`upLeft` не `null`), сдвиг не может быть меньше
   `upX − symbolOffsetX − upLeft + spaceBefore`, где `upX` — место, до которого
   занята часть строки над полосой. Берётся больший из двух сдвигов.
4. После символа: `x = symbolOffsetX + s + lineLeft + lineWidth + spaceAfter`
   (для не первого в строке это начало символа плюс `advance`). Если у символа
   есть часть над строкой, то `upX = symbolOffsetX + s + upRight + 1 + spaceAfter`,
   но не меньше прежнего `upX`.

Здесь `spaceBefore` и `spaceAfter` — свои промежутки символа, а если их нет,
то 0 и `symbolSpace`.

5. Пробел сдвигает `x` на `spaceWidth`, символ, которого нет в шрифте, — на
   `symbolSizeX`; оба сбрасывают `upX`.
6. Следующая строка ниже на `symbolSizeY`.

Правило одно для всех символов, соединяются они или нет: между строчными
полосами соседей всегда остаётся `spaceAfter` левого и `spaceBefore` правого. Связи на расстановку не
влияют, поэтому сохранённые в файле размеры и шаг годятся всегда.

Пример при `symbolSpace` 16: «Г» (`lineLeft` 11, `lineWidth` 37, `upRight` 90)
стоит так, что `symbolOffsetX + s = 0`. После неё `x = 11 + 37 + 16 = 64`,
`upX = 90 + 1 + 16 = 107`. Сдвиги ниже — тоже вместе с `symbolOffsetX`:

- «о» (`lineLeft` 14, над строкой ничего): сдвиг 64 − 14 = 50, буква встаёт
  под перекладину;
- «Ч» (`lineLeft` 52, `upLeft` 8, `spaceBefore` 8): по строчной полосе вышло
  бы 64 − 52 + 8 = 20, по верхней 107 − 8 + 8 = 107; берётся 107, чашка «Ч»
  встаёт за перекладиной «Г».

## Слитное письмо

### Когда символы соединяются

Два соседних символа соединяются, только если у первого есть `endConnection`,
а у второго есть `beginConnection`. Решают данные, а не класс символа. Отсюда:

- строчная со следующей строчной соединяется;
- заглавная продолжается следующей строчной, но к предыдущей букве не
  присоединяется;
- цифры и знаки препинания пишутся отдельно;

Место для соединительной кривой — промежуток `symbolSpace` между символами,
тот же, что и у несоединённых.

### Кривая стыка

Пусть `a` — последний элемент `endConnection` первого символа, `b` — первый
элемент `beginConnection` второго, уже сдвинутый на место второго символа
в строке. Эти два элемента не рисуются: вместо них рисуется одна кубическая
кривая. Концы связей сходиться в одной точке не обязаны.

Сначала оба элемента приводятся к кубической кривой из четырёх точек:

| Было | Четыре точки |
| --- | --- |
| `curve` | как есть |
| `curve3p` q0, q1, q2 | q0, q0 + ⅔(q1 − q0), q2 + ⅔(q1 − q2), q2 |
| `line` p0, p1 | p0, точка на трети отрезка, точка на двух третях, p1 |
| `dot` p | p, p, p, p |

Затем строится кривая стыка:

1. Концы — `a0` и `b3`: перо выходит оттуда, где начинается последний элемент
   конечной связи, и приходит туда, где кончается первый элемент начальной.
2. Вторая точка лежит на прямой `a0 → a1`, третья — на прямой `b3 → b2`. Так
   перо уходит из первой буквы и приходит во вторую в тех направлениях, как
   нарисованы связи.
3. Как далеко по этим прямым стоят вторая и третья точки, подбирается методом
   наименьших квадратов: кривая должна пройти как можно ближе к эталонной
   кривой из пяти точек `a0, a1, M, b2, b3`, где `M` — середина между `a2`
   и `b1`. Сравнение идёт в семи точках кривой.
4. Вторая и третья точки не подходят к концам ближе четверти расстояния до
   `a1` и `b2`, иначе перо пошло бы назад.

Эталон из пяти точек сам не рисуется, он нужен только как цель подгонки.

Если в связи больше одного элемента, остальные рисуются как есть: у первого
символа — все, кроме последнего, до стыка; у второго — все, кроме первого,
после стыка.

### Связь, которой не с чем соединиться

Связи рисуются только для соединения двух символов. Связь, которой не с чем
соединиться, не рисуется вовсе:

- начальная — в начале слова и после символа без конечной связи (после цифры
  или знака);
- конечная — в конце слова и перед символом без начальной связи (перед
  заглавной, цифрой, знаком).

Исключение одно: буква после буквы слитного письма, у которой нет конечной
связи. Признак по данным — у предыдущего символа есть `beginConnection`, но
нет `endConnection`; в `font0-ss` таких букв сейчас нет. Перо из такой буквы выйти не
может, поэтому следующая начинается своей начальной связью, нарисованной
целиком. На расстановку это не влияет: связь ложится в промежуток
`symbolSpace` между буквами. В `font0-ss` начальные связи выступают влево от
буквы не больше чем на 12 клеток (у «ß» на 17), так что `symbolSpace` меньше
12 делать не стоит — связь упрётся в соседа.

Символ при этом остаётся целым: в `font0-ss` все связи состоят из одного
элемента и служат только переходом, ни одна не несёт части самой буквы.
Проверено на всех 123 символах со связями — без связей каждый выглядит
законченным. Если у буквы есть штрих, который нужен ей всегда, его место
в `mainSegments`, а не в связи.

Если слитное письмо выключено, связи не рисуются ни у одного символа.

### Порядок письма

Для каждого символа слитного участка по очереди:

1. кривая стыка с предыдущим символом и остаток начальной связи, если символ
   с ним соединяется; после буквы без конечной связи — начальная связь целиком;
2. `mainSegments`;
3. конечная связь без последнего элемента, который уйдёт в стык, если символ
   соединяется со следующим.

`postSegments` всех символов участка пишутся после него, когда перо
отрывается от бумаги: перед символом, который не соединяется с предыдущим,
перед пробелом и в конце строки.

## Чего в файле нет

- Толщины линии: шрифт описывает осевую линию пера. Элемент `dot` — одна
  клетка сетки; при выводе точка рисуется кружком в толщину пера, иначе знаки
  `.` `:` `…` и точки под `!` и `?` не видны.
- Кернинга: поправок для отдельных пар символов нет и не будет.
- Высоты заглавных букв: в `font0-ss` она видна только по вспомогательной
  линии и по `top` самих букв.

## Где это в коде

| Файл | Что в нём |
| --- | --- |
| `Store.js` | поля шрифта, значения по умолчанию, загрузка, пересчёт размеров, длин, числа отрезков и клеток |
| `SymbolMeasure.js` | размеры символа |

| `Effects.js` | расстановка символов, слитное письмо, порядок письма |
